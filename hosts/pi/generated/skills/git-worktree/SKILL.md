# Git Worktree Manager

## Commands

| Command | Description |
|---------|-------------|
| `/agentic-coding-workflow:git-worktree add [name]` | Enter a native isolated worktree in this session |
| `/agentic-coding-workflow:git-worktree add --managed <branch>` | Create an owned worktree for a specialized executor |
| `/agentic-coding-workflow:git-worktree list` | Show all worktrees |
| `/agentic-coding-workflow:git-worktree remove [name]` | Remove a worktree |
| `/agentic-coding-workflow:git-worktree status` | Dashboard of all worktrees with activity |
| `/agentic-coding-workflow:git-worktree cleanup` | Find and remove finished worktrees |

## Pre-flight

```bash
git rev-parse --is-inside-work-tree 2>/dev/null || echo "NOT_A_GIT_REPO"
```

If not a git repo, inform user and stop.

For managed worktrees only, use the same `WORKTREE_OWNER_TOKEN` for all calls in a session. Scripts inherit it,
or use `CLAUDE_SESSION_ID` when available. Standalone callers should export a unique
token before creating worktrees and retain it for later cleanup. Ownership is recorded
in the linked worktree's Git metadata; existing or legacy worktrees are never adopted.

## /worktree add [name]

Use native `EnterWorktree` to create or enter the requested checkout. Report the
actual path and branch returned by the tool; a native worktree name is not an
existing branch selection. Native `ExitWorktree` owns its keep/remove lifecycle.
For a new isolated tmux session, use `claude --worktree <name> --tmux` or `/spawn`.
Do not create a manual worktree or require an existing tmux session first.
See the [native worktree documentation](https://code.claude.com/docs/en/worktrees).

### Explicit managed creation

Use this path only for `add --managed <branch>` or a specialized executor that
needs exact branch selection and the plugin's ownership/preservation contract:

```bash
bash "${CLAUDE_PLUGIN_ROOT}/skills/git-worktree/scripts/worktree-add.sh" "<branch>"
```

Output: `CREATED:<path>` or `EXISTS:<path>`. Report the actual path; an existing
worktree is not adopted. Native and user-created worktrees remain outside this
ownership contract and are preserved by automatic cleanup.

## /worktree list

```bash
bash "${CLAUDE_PLUGIN_ROOT}/skills/git-worktree/scripts/worktree-list.sh"
```

Formats output as a table: path, branch, commit. Highlights worktrees under `.claude/worktrees/`.

## /worktree remove [name]

For a native worktree, use native `ExitWorktree` with its keep/remove flow in
the owning session. The scripts below apply only to plugin-owned worktrees;
unknown ownership is preserved rather than bypassed with raw deletion.

```bash
bash "${CLAUDE_PLUGIN_ROOT}/skills/git-worktree/scripts/worktree-remove.sh" "<name>"
```

Exit codes:
- 0 + `REMOVED:` — success
- 1 + `NOT_FOUND:` — worktree not found
- 2 + `PRESERVED:<path>:<reason>` — ownership, activity, cleanliness, or merge checks failed. Report the reason and retain the worktree. `--force` does not bypass these checks.

## /worktree status

```bash
bash "${CLAUDE_PLUGIN_ROOT}/skills/git-worktree/scripts/status.sh"
```

Output is structured blocks per worktree with fields: `index`, `dir`, `branch`, `commit`, `status`, `tmux`.

If output is `NO_WORKTREES`, report that no active worktrees exist.

Format into a readable dashboard:

```
Worktree Status Dashboard
==========================

1. feature-payments [.claude/worktrees/feature-payments]
   Branch: feature/payments | Last commit: abc1234 "Add payment handler"
   Git: clean (no uncommitted changes)
   Claude: Writing tests in test_payments.py (tmux session: work:1.2)
```

For worktrees with an active tmux pane, capture recent output:

```bash
tmux capture-pane -t "$PANE_ID" -p -S -20 2>/dev/null
```

## /worktree cleanup

```bash
bash "${CLAUDE_PLUGIN_ROOT}/skills/git-worktree/scripts/cleanup.sh"
```

Output is structured blocks per worktree with fields: `dir`, `path`, `branch`, `dirty`, `merged`, `unpushed`, `action`.

If output is `NO_WORKTREES`, report that no worktrees exist and stop.

Format into a table, then use AskUserQuestion to offer:
- Remove specific worktrees by number
- Remove all eligible worktrees owned by this session

For auto-remove of merged+clean:
```bash
bash "${CLAUDE_PLUGIN_ROOT}/skills/git-worktree/scripts/cleanup.sh" --auto-remove-merged
```

**Safety:** Automatic removal requires matching ownership, no active process/lease or tmux
pane, a clean checkout including untracked files, and HEAD reachable from the target branch.
The scripts copy and verify `.claude/` artifacts under `.claude/worktree-archives/` first.
Unknown ownership, dirty or unmerged work, and failed preservation checks retain the worktree.
Report the preservation reason; do not bypass it with raw Git or filesystem deletion.

## When to Suggest Worktrees

**Use worktrees when:**
- Reviewing PR while keeping current work
- Hotfix on main without stashing
- Comparing implementations across branches
- Running tests on one branch while developing another
- Parallel Claude sessions working on different features

**Use regular branches when:**
- Simple single-branch workflow
- Small stashable changes

## Error Handling

| Error | Action |
|-------|--------|
| Not a git repo | Navigate to git repository first |
| Branch has worktree | Show existing path |
| Path exists | Suggest different name or remove |
| Uncommitted changes | Preserve and show the changes |
| Unknown ownership or active work | Preserve and report the reason |
| Branch doesn't exist | Create from HEAD |
